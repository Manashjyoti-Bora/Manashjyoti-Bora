## `01` The constraint

I do not own a development machine. That was going to be the reason I never started, so I made it the specification instead.

```console
mjb@os:~$ cat /etc/constraints
device      Android phone, 6.1 inch
shell       Termux (node, npm, git)
editor      github.dev
ram         shared with WhatsApp
budget      0
excuses     unsupported on this platform
```

Working this way removed every comfortable option. No local Docker, no 20-tab debugging, no split-screen. What survived was the part that actually matters: reading errors carefully, keeping state small enough to hold in one head, and shipping in commits small enough to type with two thumbs.

<details>
<summary><b>How this README is built (for anyone who wants to steal the technique)</b></summary>

Nothing here is a widget. The pipeline is:

1. `build_hero.py`, `build_dock.py`, `build_footer.py` emit plain SVG with SMIL (`<animate>`, `<animateMotion>`, `<animateTransform>`) on a single shared timeline, so the three acts of the banner cross-fade in sync instead of drifting.
2. Both a dark and a light variant are generated for every wide asset, then served through `<picture>` + `prefers-color-scheme`, which GitHub honours.
3. The dock tiles are ordinary `<img>` elements wrapped in `<a>` inside a table — that is the only way to make an animated SVG clickable on GitHub.
4. `.github/workflows/live-stats.yml` runs on a cron, calls the GitHub API, regenerates `assets/live-*.svg` and commits the diff back. Failures fall back to zeros so a rate limit never breaks the page.
5. Text is measured before it is drawn (`0.6 × font-size` per monospace character), which is why nothing overflows a panel on any screen width.

Constraints, again: no external image hosts, no analytics pixels, no third-party stat cards, no fonts that need downloading. It loads on a bad 4G connection in Nagaon, which is the only benchmark I trust.

</details>
