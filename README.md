## Test report

<div align="center">

<picture>
  <source media="(prefers-color-scheme: dark)" srcset="https://raw.githubusercontent.com/Manashjyoti-Bora/Manashjyoti-Bora/main/assets/testreport-dark.svg">
  <source media="(prefers-color-scheme: light)" srcset="https://raw.githubusercontent.com/Manashjyoti-Bora/Manashjyoti-Bora/main/assets/testreport-light.svg">
  <img alt="Test report: availability and latency of three live deployments, measured by a scheduled GitHub Action with real HTTPS requests." src="https://raw.githubusercontent.com/Manashjyoti-Bora/Manashjyoti-Bora/main/assets/testreport-dark.svg" width="100%">
</picture>

</div>

Every six hours a scheduled Action in this repository sends **real HTTPS GET requests** to each deployment, records the status code and the round-trip time, keeps the last 24 readings per target, and redraws the strip above. Nobody types those numbers, including me.

Availability shown on the strip is the plain ratio of successful checks to recorded checks:

$$A=\frac{1}{n}\sum_{i=1}^{n}\mathbb{1}\left[s_i=200\right]\qquad\bar{t}=\frac{1}{n}\sum_{i=1}^{n}t_i$$

where $s_i$ is the status code of check $i$, $t_i$ its latency in milliseconds and $n$ the number of readings actually stored — never a padded or invented one.

<details>
<summary><b>Reading the strip honestly</b></summary>

<br>

- The latency bar is scaled **0–400 ms**, coloured mint under 150 ms, gold up to 400 ms, coral above.
- The sparkline plots only readings that exist. With one reading you get one dot, not a fake trend line.
- Latency is measured from a GitHub runner, not from your phone in Nagaon or your laptop in Berlin. It shows that the deployment answers quickly, nothing more.
- If a site goes down, the row turns coral and stays coral until it recovers. I did not build an escape hatch.

</details>
